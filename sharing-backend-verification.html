22 live authorization checks passed

  • Created three independent anonymous sessions and a disposable team. The correct invitation admitted a second session; an invalid invitation was rejected.
  • The owner uploaded a disposable video object and answer metadata. A second member could read its transcript and download its bytes.
  • A third, unaffiliated session could not read metadata or download the object. The public object URL was inaccessible.
  • Another team member could not edit/delete the owner's answer, overwrite their video, or insert a forged owner ID.
  • Invitation hashes were inaccessible through the REST API. Malformed storage paths were rejected, and recorded question metadata was immutable.
  • An owner transcript edit became visible to the second member.
  • All synthetic objects, answers, team memberships, the disposable team and three test users were removed afterward.

These probes used the actual hosted Supabase REST, Auth and Storage APIs. The object contained synthetic test bytes, so these checks establish access control rather than video playback.
