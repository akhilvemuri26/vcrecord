Automatic preparation and answer capture

Use 15 seconds to prepare, then 20 seconds to answer. The question flow automatically starts the answer recording when preparation reaches zero and saves when the answer timer expires. Both durations are editable local preferences. This is a focused addition to the existing minimal practice screen; existing local storage, transcription, rescue, and private team sharing remain intact.

User flow

  1. First use: request a name and provide one Start practice action for browser media setup. Explain “15s to prepare · 20s to answer” and that recording starts automatically. A returning named user may automatically begin setup when the visible practice page loads; if browser activation is required, show Start practice instead of hanging. Never start in a hidden page.
  2. Acquire camera/microphone, preview playback, worklet module, and running AudioContext before starting preparation. Display a clear setup status while these are pending. If resume remains suspended, release resources and offer the explicit gesture fallback. Keep the question hidden behind the setup/onboarding state until media is ready; reveal the question and start the full preparation interval together. Next also conceals the replacement question until its preparation begins, so device latency never gives unintended extra preparation.
  3. Show phase label Prepare and a countdown from 15. Preview may be visible, but MediaRecorder and PCM collection must not start yet. At zero, start both immediately, switch label to Answer, and count down from 20. No Record answer action is required on each question.
  4. After saving, release all media resources and stay on the current question. Show Next question and Practice again. Either starts a fresh preparation/answer cycle. Next chooses a different question. Do not automatically rotate after saving.
  5. During setup/preparation, Cancel, Answers, timing settings, and Next may cancel the pending attempt; Next starts the replacement question. During recording/saving, retain Stop & save and block incompatible edits/navigation. Returning from Answers requires an explicit practice/resume action and must not unexpectedly record. Visibility loss or pagehide during setup/preparation cancels permanently; returning to the tab never restarts that attempt. During recording preserve existing stop-and-save behavior.

Important lifecycle details

  • Cancellation invalidates the attempt immediately and stops acquired tracks before waiting on pending browser promises. If permission resolves later, stop the returned tracks and do not construct/start a recorder. Check cancellation after every awaited setup stage.
  • Stop prep timers and detach listeners on every cancellation/error. Do not retain a camera/microphone stream while idle, reviewing Answers, or editing settings.
  • Prepare and answer clocks are separate: preparation time must not appear in saved video, PCM, or reported duration. Set startedAt at actual recording start and use selected answer duration for initial tick and expiry.
  • Track ended during prep cancels; track ended during recording finalizes. Keep per-attempt callbacks single-shot so completion, cancellation, permission failure, hidden tab, and recorder error cannot race into duplicate saves or stale UI.
  • Do not let transcription progress overwrite setup/preparation/recording status. Keep existing browser-storage failure download/retry/discard rescue and freeze identity while an attempt is active.
