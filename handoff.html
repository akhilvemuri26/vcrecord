VC Record — implementation handoff

14 October 2026 · Local implementation ready for independent review and root-owned publication.

A minimal static app preserves all 77 iPG questions and 7 ProTips, records camera plus microphone for up to 15 seconds, saves video and mono audio in IndexedDB, and transcribes locally using quantized Whisper tiny English. Practice retains the original centered Lato typography, white background, bordered timer and warning colors. Lato is bundled locally so remote font failures cannot delay the app.

Cofounder views

A required display name identifies the person recording. A stable local UUID is frozen with each answer; changing a name does not split identity. The answer library groups by original question order, by stable person ID, or most recent, retaining every attempt. Older records without identity appear as Unassigned. These views currently contain this browser's data only. Cross-device team sharing is pending the user's storage choice and is not implemented or claimed.

Implemented behavior

  • Shuffle without replacement across all 77 questions; new rounds after the final question.
  • Camera/microphone permission on recording action; early stop, monotonic 15-second deadline, hidden-tab partial save, frozen question and person, video/audio playback, and cleanup.
  • Atomic IndexedDB saves; quota failures retain the recording in memory with download, retry save, and explicit discard. Never displays Saved for a failed save.
  • Lazy dedicated speech worker with a single job queue, cached model download, silence detection, retry, persisted pending jobs, and a three-minute timeout. Video saves before inference.
  • Atomic transcript updates preserve saved user edits and cannot resurrect deleted answers. An open unsaved draft and playback survive background transcript updates.
  • Video and transcript download, editable transcript, per-answer delete confirmation, responsive layout and keyboard focus.
  • Locked npm dependencies, Node 22.23.0 pin, relative Vite asset base and GitHub Actions Pages workflow.

Remaining limits and publication

Root owns repository creation, commit/push, Pages activation and actual HTTPS/subpath smoke test. No commit or publication performed by the implementation manager. Actual GitHub Pages loading has not been verified locally. Relative worker/worklet URLs are configured for project paths.

Model/runtime assets initially download from Hugging Face and jsDelivr, with no audio uploaded for inference. First-use latency depends on connection and device; model download was slow on this network. Browser site-data clearing can remove recordings. No cross-device synchronization, login or backend is implemented while the storage decision remains pending. Safari and Firefox media recording were not exercised. Browser timer precision is not frame exact; actual elapsed duration is reported. No service worker, and no promise of fully offline app loading.

Browser QA scripts require a Chromium executable (CHROMIUM_EXECUTABLE supported by transcription/resilience scripts), preview on port4173, and a generated WAV at /tmp/vcrecord-spoken.wav. The transcription script uses a temporary dist/fixture.wav, which is not source controlled and is removed by the final build. Synthetic speech and screenshots stay outside the source repository. npm scripts provide unit tests and the production build. No no-mistakes pipeline invoked.
