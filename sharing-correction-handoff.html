Cross-tab sharing correction

14 October 2026 · The P1 deleted-recording resurrection identified in sharing-review.html is corrected. The original implementation and backend scope remain governed by sharing-handoff.html and sharing-backend-verification.html.

Behavior

Every shared recording drain now acquires the same origin-wide exclusive Web Lock named vcrecord:shared-answer-sync. The lock covers reading durable records, sending uploads/updates/deletions, and acknowledging successful revisions. Each tab retains its existing local active-drain and request-version handling, so repeated triggers while waiting join the queued drain. The winning tab reads current IndexedDB state after acquiring the lock.

A tab can still mark a durable tombstone while another tab uploads. That upload must finish before a drain deletes the remote metadata and video object and removes the tombstone, preventing the earlier upload from completing after deletion. Newer durable edits are sent after an older upload and only the matching revision is acknowledged.

If Web Locks are unavailable or acquiring the lock fails, pending records receive an explicit sync-unavailable error. Their local Blob, edits and deletion tombstones remain durable, and no sharing network write runs without the lock. Users need Web Locks on a secure origin to sync sharing.

Validation

  • Node 22.23.0 matches the repository pin and package engines.
  • Four focused tests pass in tests/sync-cross-tab.test.mjs. Separate transpiled instances of the real sync module share a durable-storage adapter, remote metadata/object adapter and named-lock manager, representing independent tab state.
  • Paused initial upload plus deletion in the other tab: the tombstone survives while the upload is paused; after release both local and remote metadata/object are absent.
  • Queued drain plus repeated triggers and overlapping durable edits: the remote transcript ends at the newest revision and the local record is synced.
  • Unavailable and rejected Web Locks: local video and tombstones survive, callbacks refresh the UI, and zero remote writes occur.
  • Final npm run build passes TypeScript and Vite production compilation. Final bounded unit suite passes all 15 tests.

The focused tests model cross-tab modules and lock serialization deterministically; they do not repeat the live backend/browser matrix already completed by the original implementation manager. An independent Astra rereview of this correction remains with the root coordinator.
