P1 — Multiple tabs can resurrect a deleted shared recording

src/sync.ts:54–58, 84–104: activeDrain serializes requests only inside one tab. IndexedDB and anonymous identity are shared across same-origin tabs. If tab A is uploading an answer while tab B marks it deleted, tab B can delete the remote state and remove the local tombstone. Tab A then finishes uploading and inserts the answer again. Its bookkeeping finds no local record; no deletion remains to retry. The deleted video and transcript are visible to team members again.

A focused reproduction instantiated the real transpiled sync module twice with one shared in-memory storage adapter and paused the first upload. After the second tab deleted the answer, both local and remote records were absent. Releasing the first upload left localExists: false and remoteExists: true. This is a deterministic resurrection, not a hypothetical authorization bypass.

Serialize the entire read/send/acknowledge drain across tabs, for example with a named Web Lock on supported secure origins, and define a safe fallback for browsers without that capability. Add a focused two-tab regression that pauses initial upload, deletes in the other tab, resumes, and verifies that both remote metadata/object and the local tombstone are eventually absent. Also check that overlapping edits finish with the newest durable revision.
