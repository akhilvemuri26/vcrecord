14 October 2026 · Fresh Astra review · Initial implementation, before correction pass

Decision: corrections required before publication. Two P2 lifecycle/data-preservation defects were found. No critical security defect was identified in the reviewed local-only implementation. Cross-device sharing remains explicitly pending a user decision and is not represented as completed.

P2 — Hiding during capture setup can leave the camera active and start recording in the background

src/capture.ts:61–81, with lifecycle listeners registered only at lines 193–196.

Trigger: start recording, then hide the page while camera permission, preview playback, worklet loading, or audio-context resume is pending. The hidden transition occurs before the visibility listener exists. Setup proceeds and starts the recorder without checking whether the page is already hidden. During a stalled setup, acquired media tracks also remain live without a hide handler.

Impact: the app can use camera/microphone while the page is hidden and can bypass its intended hidden-tab stop safeguard. Its deadline then depends on background timer scheduling.

Evidence: focused reproduction on pinned Node 22.23.0 with DOM/media test doubles, hiding while getUserMedia was pending and resolving it afterward, returned {visibility:"hidden", recordingState:"recording", cameraTrackState:"live"}. The test explicitly stopped the handle and verified the track ended. This is a deterministic lifecycle reproduction; it is not a claim of cross-browser timer behavior.

Correction and acceptance: install cancellation/lifecycle handling from the start of setup, promptly release any acquired tracks when hidden, and prevent late setup completions from starting recording. Test hiding during delayed media permission and delayed preview/worklet setup; ensure no recording begins, tracks end, and ordinary foreground capture still works.

P2 — Typing while a transcript save finishes can lose newer edits

src/main.ts:387–395, interacting with the dirty guard at lines 339–342.

Trigger: click Save transcript and continue typing after the update callback has put the saved value but before the IndexedDB transaction completes. The new input sets the dirty marker. When the save promise resolves, the handler unconditionally removes that marker and refreshes the library.

Impact: renderDetail treats the newer draft as clean and replaces it with the earlier saved transcript. A normal asynchronous save can silently erase text entered while it was finishing.

Evidence: source-level ordering: updateAnswer resolves only on transaction completion, while the save callback reads textarea.value before that completion; the post-await handler always clears dirty. Background transcription refreshes correctly respect dirty, so the defect is specifically the explicit save completion.

Correction and acceptance: snapshot the text and edit revision on click, persist that snapshot, and clear dirty only if no later input occurred. Delay transaction completion in a focused test, enter additional text during the save, then verify the stored snapshot and preserved newer draft. A later save must persist the newer draft.

Accepted implementation areas

  • Reviewed the complete application source, capture worklet, storage transactions, worker queue, package/deployment configuration, plan, handoff, and test scripts.
  • IndexedDB updates are transactional and do not recreate deleted answers. Completed recognition preserves explicitly saved transcript edits. Dirty drafts and existing video elements survive ordinary background library refreshes.
  • Normal capture completion stops tracks, disconnects audio nodes, closes its AudioContext, and clears lifecycle listeners/timers. Failed storage retains an in-memory recording with rescue actions.
  • Transcripts and names are inserted as text or textarea values. No privileged backend secret or media upload path was found. Recognition uses local WASM after external model/runtime downloads.
  • Original-corpus parity, real browser capture/playback, actual Whisper transcription, mobile layout, and normal hidden-tab/quota/permission behavior are reported as passing in the implementation handoff. These broad tests were not rerun by this reviewer.
