VC Record

Implementation plan · 14 October 2026

Build a minimal interview practice app in the style of iPG, retaining every original question. Each answer records camera video and microphone audio for up to 15 seconds, saves locally, and receives a free on-device transcript. A cofounder answer library provides playback and transcripts after reload, grouped by question or person. Publish the static app to GitHub Pages.

Product and design

Reading this as a compact YC interview practice tool that preserves the original sparse typography, centered question, simple timer, and restrained controls. Inspect the recovered stylesheet or screenshot and reuse its visual language; avoid a marketing landing page, decorative cards, or new visual branding.

  1. Practice: one original question, question position, 15-second timer, a modest camera preview, and “Record answer.” Request camera and microphone only on this action. Start the timer only once recording actually begins.
  2. During recording: visible recording state, countdown, and “Stop & save.” Disable question navigation and repeat recording actions. Auto-stop at the deadline, then immediately save. The current question and ID must be frozen into that answer.
  3. After recording: concise saved feedback, transcript progress or result, “Record again,” and “Next question.” Multiple attempts remain in the library. Shuffle without replacement; offer a new round after all questions. Keep text accessible and keyboard actions subordinate to focused inputs, buttons, and video controls.
  4. Answers: two simple grouping controls, “By question” and “By person.” Default to question groups; show each person’s attempts within a question with clear name labels. Person groups show all of that person’s answers quickly. Rows show question, person, date/time, duration, transcript status, and one native video player for the selected attempt. Include transcript editing, retry transcription, recording download, and deletion with an explicit per-item confirmation. Provide an empty state and a return-to-practice control.

Use ordinary responsive document flow, no fixed footer overlap, legible focus states, real buttons, and labelled media controls. Preserve the original tips if available and attribution with a link. A 15-second interval cannot be guaranteed to the frame by browser timers; implement a monotonic deadline and stop on page hiding to avoid background-throttled overlong answers.

Transcription decision and honest limits

Use local Whisper by default. It has no paid API per answer and processes the saved recording on the visitor's device. The initial model/runtime download can be tens of megabytes and slower devices take longer. Once downloaded, cached model assets can permit later offline inference, but do not promise fully offline app loading without a tested service worker. Never put a paid transcription key or privileged backend secret in the frontend. A configured backend publishable client key is distinct from a privileged secret and must be protected by enforced access policies.

Browser SpeechRecognition is not the primary implementation: availability and behavior vary by browser, and some browser implementations use an external recognition service. It cannot reliably retranscribe an already-saved recording across supported browsers. If adopted as an optional fallback, disclose its processing location and limitations rather than calling it local or universally supported.

Save the video before beginning inference. Transcript failure must leave a playable, downloadable answer with a retry action and editable text. Persist pending jobs and restore/retry them after reload. Distinguish “No speech detected,” failed model download, unsupported runtime, and empty recognition. A light silence check reduces invented text on silent recordings. Render transcript strings as text, never HTML. Preserve a user edit when a late inference result arrives, or require an explicit replacement.

Verified official pipeline documentation confirms @huggingface/transformers, the automatic-speech-recognition pipeline, browser-cache model downloads, quantized dtype support, and a Xenova/whisper-tiny.en example. Its stable documentation link currently targets v3.8.1; pin a tested published version and consult its matching docs rather than main-only APIs. Also consult MediaRecorder and SpeechRecognition.

Failure handling that protects answers

  • Handle denied permission, missing devices, camera busy, insecure context, unsupported recording, ended tracks, and rapid double clicks. Never create an empty answer after capture failure.
  • Use an explicit capture state machine: idle → requesting → recording → stopping → saving → idle/error. Stop/finalize is idempotent. Wait for final dataavailable and stop before assembling and persisting the Blob.
  • Clear the deadline and stop all media tracks even if storage fails. Keep the completed Blob in memory and offer immediate download if quota/storage fails; do not falsely display “Saved.”
  • Stop and preserve the current partial recording on page hiding; warn before a navigation that would discard an unfinished save. Refresh during an active capture cannot be represented as a completed saved answer.
  • Prevent a stale transcript job from resurrecting a deleted answer. Revoke object URLs when replaced or removed; release database connections and worker resources as appropriate.

Acceptance and validation

  • Corpus: every upstream question is present with exact wording; fixture parity test proves count and contents, and shuffle eventually reaches all items without accidental omission.
  • Capture: test with browser fake camera and a known spoken-audio fixture. Confirm video and audio tracks, nonempty Blob, early stop, 15-second auto-stop tolerance, one save only, correct question snapshot, and track cleanup after every path.
  • Persistence: reload and play a saved answer; observe a real transcript; verify local-only mode isolates independent browser contexts and the chosen sharing mode deliberately transfers the authorized team’s answers. Check repeated attempts, transcript edits, deletion, and download.
  • Transcription: exercise a real model on known spoken audio, not only a stub. Test blocked model fetch and retry, silence, queued work after reload, and deletion during inference. Record model/version and elapsed result, without promising a universal latency.
  • Resilience: permission rejection, unsupported media, quota failure, rapid controls, hidden tab, and stale async completions must produce understandable states with no leaked camera tracks.
  • Layout: inspect at approximately 390 px and 1440 px widths; long questions/transcripts wrap; keyboard focus and answer playback work. Confirm original stylistic fidelity from actual reference.
  • Build and deploy: one manager-owned typecheck/build; Playwright one worker. Test production build under the Pages subpath, including worker/worklet/WASM URLs and model CORS. Root confirms actual HTTPS URL and Pages deployment success.
  • Resource cleanup: stop only task-owned localhost servers immediately after active QA and before handoff. Verify processes are stopped. Never invoke no-mistakes.
